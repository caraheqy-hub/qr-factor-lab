# GM SDK 故障记录（2026-10-04）

**症状**：`PYTHONPATH=deps` 后 `from gm.api import ...` 报 `ModuleNotFoundError`；`deps/gm` 本身拒绝目录枚举。此前 2026-10-03 同一项目的历史数据查询成功。未读取或记录 `GM_TOKEN` 内容。

**证据与原因**：本轮 `deps/gm`、新安装的 `deps_gm_repair/gm` 都禁止子目录权限继承，且子目录 ACL 缺少当前 Codex 沙箱用户的读权限；父目录有权限。`gm` 因而被 Python 当成空的 namespace 包。对隔离副本 `deps_gm_repair/gm` 在提权的工作区命令中恢复继承权限后，报错前进到 protobuf 解析，证明首个故障是文件 ACL。全局 Anaconda protobuf 为 5.29.3，而 GM 3.0.187 的生成代码需要 3.20.x；将 `protobuf==3.20.3` 安装在隔离目录并同样恢复 `google` 子目录继承后，核验从隔离目录加载到 3.20.3，`gm.api` 可导入。原 `deps/gm` 未改动。

**剩余故障**：用隔离副本运行 [`probe_gm_all_a_universe.py`](probe_gm_all_a_universe.py) 已进入 `get_instrumentinfos`，返回 GM 状态 **1001“无法连接到终端服务”**；默认沙箱与提权运行都相同。本地 SDK `gm/api/errors.py` 将无效 token 单列为状态 1000、终端服务连接为 1001；[掘金官方 token 说明](https://www.myquant.cn/docs/python/python_other_api)也把无效 token 视为独立错误。本轮进程列表未观察到名称匹配 Goldminer/GM/MyQuant 的进程，但仅凭进程名和 SDK 错误不能确认是本机终端未启动、网络服务中断还是其他连接配置。不能把 1001 归咎于 token；全 A 股元数据仍未取得。SDK 初始化另提示用户目录日志文件无法写入，本轮已成功越过导入并执行接口调用，故日志提示不是这次 1001 的直接证据。

**最小复查**（在掘金终端及其数据服务可用时）：

```powershell
$env:PYTHONPATH=(Resolve-Path .\deps_gm_repair).Path
python -c "import google.protobuf; print(google.protobuf.__version__)"
python research\probe_gm_all_a_universe.py
```

应先看到 protobuf `3.20.3`，然后仅输出元数据行数、字段名和历史上市数量。若仍为 1001，先在用户会话检查掘金终端/数据服务是否运行并可联网，再复查 SDK 服务地址；不要在日志或聊天里输出密钥。此次状态为**导入故障已修复、数据服务连接未解决**。复现守卫是安装到隔离目录后立刻测试子目录 ACL、依赖版本、`gm.api` 导入和一条只读查询，不以 pip 成功信息代替接口验证。
